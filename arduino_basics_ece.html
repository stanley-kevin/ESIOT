1. Introduction

Arduino is an open-source embedded platform: a microcontroller board plus a simplified C/C++ framework (the Arduino core) and an IDE. A sketch (.ino file) is compiled with avr-gcc, uploaded through a bootloader, and runs bare-metal on the MCU. The reference board here is the Arduino Uno R3 (ATmega328P).

Operating principle: the CPU fetches instructions from flash, reads inputs (digital pins, ADC, serial), processes them in SRAM, and drives outputs (GPIO, PWM, serial) in an endless loop.

Why it matters: it is the quickest route from concept to working hardware, and the GPIO/ADC/PWM/UART/I²C/timer concepts transfer directly to STM32, ESP32 and industrial MCUs.

Prerequisites: basic C (variables, functions, operators), Ohm's law, logic levels, binary/hex numbers.

3. Working principle

const int LED = 9, POT = A0;
void setup() {            // runs once after reset
  pinMode(LED, OUTPUT);
  Serial.begin(9600);
}
void loop() {             // repeats forever
  int raw = analogRead(POT);          // 0..1023
  analogWrite(LED, raw / 4);          // 0..255
  Serial.println(raw);
  delay(100);
}
  1. Power/reset: the bootloader runs briefly, then jumps to the sketch.
  2. Hidden main(): initialises timers and calls setup() once, then calls loop() repeatedly.
  3. Signal flow: pot voltage → ADC count → scaled to 8 bits → PWM duty → LED average brightness; the raw value goes to the PC over UART.

Advantages, limits, design cautions

Advantages: low cost, huge library ecosystem, fast prototyping. Limits: 2 KB SRAM, 8-bit CPU, no OS, abstraction hides timing detail. Cautions: respect pin current limits; use a transistor/driver for motors and relays; avoid long delay() in responsive code; use String objects sparingly on small SRAM (heap fragmentation).

Common misconceptions: (1) analogWrite does not produce a true analog voltage. (2) analogRead returns a count, not volts. (3) delay() blocks the CPU, though interrupts still run. (4) Unconnected input pins float; they do not read LOW.

4. Waveforms (illustrative)

The LED or RC filter responds to the average value Vavg = D × 5 V. Multisim can simulate analog parts of this circuit (LED, resistor, RC filter, sensors) using a pulse source; a full Uno sketch runs in Arduino-specific simulators instead.

5. Equations

ADC count
N = floor( Vin · 2n / Vref ), n = 10 → 0…1023
Vin in volts, Vref = 5 V default. LSB = Vref/2n = 5/1024 ≈ 4.88 mV. Reconstructed voltage ≈ N × LSB (arduino reference text often uses 1023; error is under 1 LSB).
PWM duty and average
D = value / 255, Vavg = D · VH, T = 1/fPWM
Derivation: Vavg = (1/T)∫0Tv dt = (VH·ton)/T = D·VH. Limits: value 0 → 0 V, 255 → 5 V constant.
LED series resistor
R = (VCC − VF) / IF
Use the next standard value above R, so current is slightly lower. Keep IF ≤ 20 mA per pin.
Timer overflow frequency
fovf = fclk / (Npre · 2b)
Npre = prescaler, b = timer bits. Uno default PWM: 16 MHz / (64 × 256) ≈ 976 Hz on D5, D6 (about 490 Hz on D3, D9, D10, D11).
UART baud register (normal mode)
UBRR = fosc / (16 · baud) − 1
Round to the nearest integer; baud error = (actual − target)/target.
Pull-up/Pull-down current: I = V/R. Internal pull-up ≈ 20–50 kΩ gives about 0.1–0.25 mA at 5 V.

6. Solved problems

P1 (Easy) ADC count

A sensor outputs 2.5 V; Vref = 5 V, 10-bit ADC. Find N and the resolution.

N = floor(2.5 × 1024 / 5) = floor(512) = 512. LSB = 5/1024 = 4.88 mV.

Interpretation: mid-scale input gives mid-scale count.

P2 (Moderate) LED resistor

5 V supply, red LED VF = 2 V, IF = 10 mA. Choose R.

R = (5 − 2)/0.010 = 300 Ω → standard value 330 Ω. Actual I = 3/330 = 9.09 mA. Power in R = I²R = (9.09 mA)² × 330 ≈ 27 mW (a ¼ W resistor is ample).

P3 (Difficult, GATE-style) PWM average and timing

analogWrite(9, 191) on an Uno (490 Hz). Find duty, Vavg, T and ton.

D = 191/255 = 0.749. Vavg = 0.749 × 5 = 3.745 V. T = 1/490 = 2.04 ms. ton = 0.749 × 2.04 = 1.53 ms.

Shortcut: value/255 ≈ value/256; 191 is about 3/4 of full scale, so about 3.75 V.

8. Interview preparation

Industry perspective: Arduino is used for proof-of-concept boards, test fixtures, sensor characterisation and teaching. Production products move to bare MCUs (STM32, ESP32, NXP) with the same concepts: register-level GPIO/ADC/timer setup, RTOS, low-power design and a hardware-validation plan. Interviewers value timing thinking (non-blocking code, interrupts), electrical sense (current limits, pull-ups) and debugging method.

Common errors and troubleshooting

  • Upload fails: wrong board/port, Serial monitor or another app holding the port, D0/D1 loaded.
  • LED dim or dead: reversed polarity, missing resistor, wrong pin number.
  • Button random: floating input; use INPUT_PULLUP and active-LOW logic.
  • Garbage in Serial Monitor: baud mismatch.
  • Resets under load: motor/servo powered from the 5 V pin; use an external supply with common ground.
  • analogWrite fails: pin is not PWM-capable (the tilde ~ pins).

Memory aids: PWM pins D3 5 6 9 10 11 ("3-5-6, 9-10-11"). Unpressed button with pull-up reads 1, pressed reads 0.
